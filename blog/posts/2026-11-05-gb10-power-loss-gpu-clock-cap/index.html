GB10 整机无预警断电：GPU 频率上限与并发推理的排查记录

2026-11-05#nvidia#gb10#dgx-spark#gpu#power#linux#troubleshooting

Update, 2026-11-07

The 884–2418 MHz lock below is the stock application clock, not a reduction. It does not keep these boards under the hard power cut. The journal pass, the reason a power limit cannot be set, and the governor that is running now are in GB10 hard power-off and the clock-cap thermal governor.

背景

手上有一台 HP ZGX Nano G1n（NVIDIA GB10，128 GB 统一内存，DGX OS 系列）和一台同型号机器，两台通过 200GbE 直连组成双机张量并行，跑 GLM-5.3-Flash 的本地推理服务。推理引擎是 TensorFold，配置里 --parallel 4，允许四路并发请求。

现象

2026-11-05 20:42:30（+08）左右，整机直接断电，没有任何关机流程：

  • 断电前 GPU 空闲约 3 小时 40 分钟。
  • 断电前约 45 秒开始一个 31k token 级别的 prefill 请求（20:41:46）；约 19 秒后（20:42:10 与 20:42:11）又有两路请求并发进入，断电时正处于并发 prefill 阶段。
  • 断电后两台机器都掉了一根 200GbE 链路；重启后硬件 RTC 被复位到 2000 年，说明 RTC 也一起断电。

排查结论

  1. 不是系统关机。 journalctl 显示 journal 是非正常关闭后重建的；重启时硬件 RTC 被复位到 2000-01-01T00:00:00 UTC。只有板级供电（包括 RTC 备用电源）整体掉电才会这样，正常重启时 RTC 会保留时间。
  2. 没有软件层面的先兆。 断电前的内核日志里没有 NVRM/Xid 报错、PCIe AER、MCE、watchdog 或 OOM。重启后 ACPI 热区读数为 55–58 °C，远低于触发阈值；断电前 CPU 空闲超过 99%，内存空闲约 76%。
  3. 时间上的相关性。 断电发生在 GPU 从空闲突然拉到满功率 prefill 的窗口内。这只是时间上的相关，并没有直接测到瞬时功耗。我的假设是：并发 prefill 带来的瞬时电流尖峰超过了整机供电的瞬态余量。这个假设还没有被证实。

处理

1. 降低并发。 把推理服务从 --parallel 4 改为 --parallel 1，避免 omp 的后台标题生成请求和主对话请求同时打到 GPU 上。

2. 限制 GPU 图形频率上限。 GB10 的最大加速频率是 3003 MHz，默认应用频率是 2418 MHz。把频率窗口锁在 884–2418 MHz，减小高频满载时的瞬态功耗峰值：

sudo nvidia-smi -lgc 884,2418   # 锁定频率范围
sudo nvidia-smi -rgc            # 撤销锁定

nvidia-smi -lgc 的设置在驱动重载或重启后会丢失，所以我用 systemd oneshot 单元把它固化下来：

[Unit]
Description=Lock NVIDIA GB10 GPU graphics clock ceiling (884-2418 MHz)
After=nvidia-persistenced.service
Wants=nvidia-persistenced.service

[Service]
Type=oneshot
ExecStart=/usr/bin/nvidia-smi -lgc 884,2418
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target

保存为 /etc/systemd/system/nvidia-clock-lock.service，然后执行 systemctl daemon-reload && systemctl enable --now nvidia-clock-lock.service。

还没有解决的问题

  • 根因未确定。 频率上限是缓解措施，不是修复。我没有测量断电瞬间的功耗或电压，因此无法确认是电源瞬态还是别的原因。
  • 效果未验证。 频率上限对满载 prefill 时的功耗有多大影响，还没有在负载下实测。重启后持久化也还没有实际重启验证。
  • 社区也有类似报告。 NVIDIA 开发者论坛上有多个 GB10 整机（HP、ASUS、Dell 等型号）在高负载时硬断电的帖子。一篇 8 台 GB10 的测试记录称，持久化锁频后断电明显减少甚至消失，但作者同样说根因未证实。这些都是个人经验，没有统一的复现条件。
  • HP 固件与 BIOS。 这台机器的 BIOS 是 5.36，EC 与 fwupd 显示已是最新版本。我没有找到与断电直接对应的固件修复说明。

如果你也在跑 GB10 上的大上下文并发推理，建议先把并发数降到 1，再观察是否仍然断电。
