SC117 的 abliterated Qwen3.8-Flash-Next（IQ3_XXS）：一份不在 Strata 名单里的 cook，在一块 GB10 上当日常模型

2026-11-19#qwen3.8#flash-next#abliterated#strata#moe#quantization#gb10#dgx-spark#self-hosted

TL;DR: SC117 把 ISTA-DASLab 的 Qwen3.8-Flash-Next GSQ-RCO 做成 abliterated（去拒绝）版，出 Q2_0 / IQ2_XS / IQ3_XXS / IQ3_S 四档，还额外发一个给 Strata 用的 strata/rt 草稿层。IQ3_XXS 那份两 shards（44.06 + 26.82 GiB）在 Strata 0.1.62 上以 262,144 上下文 + 视觉常驻跑在单块 GB10（DGX Spark，121 GiB 统一内存）上：11-19 引擎自己记的账是 203 个真实请求平均 52.9 tok/s（区间 10.0–70.6），1,765 / 1,842 / 2,255 token 的长回复稳在 52–55 tok/s，一个 105,851 token 的 prompt 读了 53 s（≈2,000 tok/s），expert cache 命中 99.8%，整机内存 89 / 121 GiB。别扭但有意思的一点：这份权重不在 Strata 上架的 23 个 pack 名单里——按指纹差一个 tensor——引擎照跑不误。这篇帖子本身，就是这台机器上这个模型驱动一个编码 agent 写的。

上一篇讲的是三个引擎怎么把 Flash-Next 装进 GB10（tqLLM / Strata / TensorFold）；这篇讲装好之后换一份 cook 会发生什么。

这份 cook 是什么

repo：SC117/Qwen3.8-Flash-Next-GSQ-RCO-abliterated-GGUF。base 是原厂的 ISTA-DASLab/Qwen3.8-Flash-Next-GSQ-RCO-GGUF（GSQ-RCO 是原厂自己的量化配方）。SC117 做的事：同一个模型 → abliterate（把拒绝 / “作为 AI 我不能…” 那一层行为去掉）→ 自己重新出四个档位，每档两个 shards；顺带放了别的引擎要的 mtp-*.gguf、跟原厂同名同尺寸的 mmproj-Qwen3.8-Flash-Next-BF16.gguf，以及给 Strata 的 strata/rt/。

本机在用的东西：

文件字节作用
IQ3_XXS/…-00001-of-00002.gguf47,342,144,896（44.06 GiB）shard 1：dense + routed experts，--native 吃它
IQ3_XXS/…-00002-of-00002.gguf28,800,138,432（26.82 GiB）shard 2：PLE 表，--ple-gguf 吃它
strata/rt/experts.bin707,788,800草稿层 experts
strata/rt/dense.bin116,099,072草稿层 dense
strata/rt/draft_vocab.bin425,196草稿词表

models.md 里那句 “SC117 strata/rt MTP drafter” 一直让人以为是某个 HF org —— 它只是这份 repo 里的一个子目录。

为什么它不在名单里，但能跑

Strata 的模型面是硬名单。terminal/setup.py 里的 FAMILIES / MODELS 只有 qwen / swift / coder / unsloth / gyro / nvfp4（外加一条自己走 engine path 的 qwen36）；权重清单落在 terminal/data/gguf_fingerprints.json，23 行，每行写死 arch、tensor 数、payload 字节、每类 expert 用到的量化格式、shard 文件名和 HF repo，全部 arch = qwen4exp。文件里还有一张 _roles，规定每个 tensor 名允许出现哪些量化格式，例如 blk.N.attn_gate.weight 允许 IQ3_S / IQ4_XS / Q2_0 / Q3_K / Q4_K / Q5_K / Q6_K / Q8_0。

认一份现成的 GGUF 靠 strata_control/models.py 的 known_set_by_header()：所有 shard 的 tensor 数、总 payload 字节、expert 格式集合三者同时等于名单里某一行才算"认识"。SC117 这份不等：

tensor 数payload 字节
名单 qwen/IQ3_XXS（原厂）122475,828,974,080
SC117 IQ3_XXS122376,142,283,328

于是 known_set_by_header() 返回 None，strata models import --plan 给的是：

"architecture": "qwen4exp", "tensor_count_scanned": 1223,
"adoption_status": "requires_architecture_quantization_tokenizer_and_engine_checks"
"A known shard name is only a selection hint; it does not prove provenance or file integrity"

翻译成人话：布局合法、格式在允许集合里，但不是上架产品，所以要走架构 / 量化 / tokenizer / 引擎版本 / 硬件五项人工确认。expert 格式确实是那七种（IQ2_S / IQ2_XS / IQ2_XXS / IQ3_S / IQ3_XXS / IQ4_NL / Q2_0），加上 SC117 自己配好了 rt 草稿层，所以做法就是手建 pack、手写 config。少掉的那一个 tensor 是哪一个，我没 diff（原厂 IQ3_XXS 不在本机）。

顺手打掉一个可能的误解：“abliterated 版是不是引擎特别照顾”。同一晚非 abliterated 的 Unsloth UD-IQ3_XXS 用同一个 SC117 草稿层跑，48.1 tok/s @ 262K（0.1.59 时代的 bench log，92 GiB）。引擎只看 layout + 量化格式 + 草稿层，权重被没被 abliterate 它既不知道也不关心。

跑起来什么样

条件：GB10（DGX Spark，121 GiB 统一内存）、Strata checkout v0.2.16、engine 组件 0.1.62、context 262,144、images on、--spec 4（MTP 草稿层）、--mmap-experts、temperature 0.7。启动报账（log 原文，IP 打码）：

[strata] mapping the experts from the model files (about 47 GB, --mmap-experts):
         they are not loaded into RAM - the OS file cache reads them as the GPU's
         expert cache fills and as requests need them.
[strata] filling the GPU's expert cache (20741 experts, 33.78 GiB of VRAM) ...
[strata] Drafting: MTP (the DFlash2 drafter isn't downloaded yet)
ready: http://<本机局域网 IP>:8881/v1 (context 262144 tokens, images on)

11-19 引擎自己记的真实请求：

[strata] reading the prompt: 105,846 of 105,851 tokens, 53 s so far
[strata] done: 2255 tokens in 44 s (52.2 tok/s), expert cache 99.8% hit
[strata] done: 1842 tokens in 36 s (55.2 tok/s), expert cache 99.8% hit
[strata] done: 1765 tokens in 34 s (55.4 tok/s), expert cache 99.8% hit

同一个 log 到 11-19 深夜为止一共 203 个请求，平均 52.9 tok/s，最低 10.0（几个两三个 token 的烟测）、最高 70.6。11-19 深夜我另外用脚本打了一轮做对照：thinking off 时 230 token / 5.37 s = 42.8 tok/s，thinking medium 时 460 token / 9.61 s = 47.9 tok/s（reasoning 815 字符），32,219 token 的 prompt 读 15.31 s = 2,125 tok/s prefill，同一时刻在 Spark 上 free -g 读到 89 GiB used / 121（agent 会话还在跑）。短请求的 tok/s 会被首 token 之前的开销压低，稳态看上面那三行长请求。

2026-11-14 那份 bench log（engine 0.1.59，同一台机器）的引用数字：47–48 tok/s decode、prefill 2.0–2.8k tok/s 打到 100K prompt（53K prompt 1,983 / 99K prompt 2,798）、262K 上下文 ~85 GiB；--spec 2/4/6 = 44.7 / 48.1 / 45.7 tok/s；spec4 在 32K 上下文 53.6 tok/s。草稿层关不掉：

native (IQ) pack: it needs --native SHARD1, --spec T (T >= 2) and --prefill CHUNK

也就是说 85 GiB 那个数里有一份是 MTP，它不是"可选加速"而是这套 native IQ pack 的进场条件。

主观：为什么"感觉好用"，以及代价在哪

能落到证据上的三条：

  1. 不断线。作为编码 agent 的驱动模型跑了一整天，没有"作为 AI 我不能…“那一类回弹，工具调用照常。abliteration 在这里的价值不是更聪明，是少一层劝退。
  2. thinking 有档位且真的生效。同一条 prompt：reasoning_effort=none 出 0 字符 reasoning，medium 出 815 字符。11-14 那轮在端点上测的是 reasoning tokens 0 / 118 / 95 / 197（none / low / medium / max）。引擎还会主动把 thinking 限到 max_tokens 的 24,576，给答案正文留位置。
  3. 262K 上下文 + 视觉是真能用的：那个 105,851 token 的 prompt 是当天真实请求，53 s 读完，之后 55 tok/s 出正文，expert cache 99.8% 命中。

代价也要说清楚。IQ3_XXS 是 Strata 质量阶梯上最低的一档（引用 docs/QUANTS.md，那张表是在 AMD 机器 + Q8_0 参照上量的，不是我量的）：

量化与 Q8_0 同 top-1mean KLPPL（Q8_0 = 4.052）

UD-Q4_K_XL93.09%0.0564.068
UD-IQ4_XS88.91%0.1014.120

“够用"是把 125B MoE 塞进一块 121 GiB 统一内存的机器、还带 262K 上下文和视觉这件事换来的。要升级就是同 repo 的 IQ3_S/：原厂同档 payload 77.9 GiB（IQ3_XXS 是 70.6 GiB），本机可用上限约 96.8 GiB，草稿层又是必需品——所以 IQ3_S 在 262K 上下文下未必装得下，降上下文能省 3–4 GiB。这条是从 payload 和上限推的，我没下载 IQ3_S 去撞一遍。

想复制的话

Strata 的 CLI 不会替你去 HF 拉名单外的东西——strata install --family qwen --model IQ3_S 只会拿它自己表里的 repo。名单外就手动：

# 1) 在有 HF DNS 的机器上拉：IQ3_XXS/ 两 shards + strata/rt/ 四文件，sha256 对过再 rsync 到 owner 机器
# 2) 建 pack（tokenizer / dense / n-gram 表）
# 3) 手写 config 的关键 args：
#    --native   <shard1>   --ple-gguf <shard2>   --mtp <strata-rt 目录>   --spec 4
#    --mtp-q4 all --mtp-hnorm stream --expert-profile <engine 自带 expert-profile.bin>
#    --expert-cache 20741 --prefill auto:32768 --max-context 262144
#    --kv int8 --mmap-experts --kv-resident 32768 --vram-reserve-mib 700 --vision
# 4) 起服务：
.venv/bin/python terminal/serve/server.py --engine strata --config <那份 json> \
    --host <本机局域网 IP> --port 8881

一个端口一个模型，换档就是停掉再起。名单内想省事的对照是 strata launch --plan --family qwen --model iq3_s（只打印计划，不下载、不改机器）。

没验证的

  • 没在本机跑 Strata 的 quant_quality.py，上面 KL / PPL 那张表是引用。
  • abliterated 会不会让工具调用或指令跟随变差，没跑对照集，只有"一整天没出乱子"这种体感。
  • SC117 与原厂 IQ3_XXS 的 tensor 差集没 diff。
  • IQ3_S 档位没下载，容量结论是推的。
  • 42.8 tok/s 这类短请求数字含首 token 前的开销；稳态看 52–55 tok/s 那三行。
